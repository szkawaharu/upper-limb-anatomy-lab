# v0.71.0 — Direction-locked shoulder drag

## 症状

v0.70の録画では、腕を挙上する途中で上腕〜前腕の向きがねじれて見えることがあった。

v0.68.1ではpointer-down時の姿勢と指位置は固定していたが、画面上の移動量を `挙上角 + 挙上面` へ変換する局所ヤコビアンを**現在姿勢から毎回再計算**していた。

そのため、同じ画面方向へ指を動かしていても腕が上がるにつれて、

- 「この画面方向 = 挙上」
- 「この画面方向 = 挙上面変更」

の比率が徐々に変化し得た。

特に挙上0°付近と180°付近では挙上面が数学的にほぼ未定義で、わずかな挙上面変化が上腕のrollのように見えやすい。

## v0.71の変更

### 1. 最初の意味のあるスワイプで方向を1回だけ決める

pointer-down直後の微小なノイズは使わず、約7 px以上移動した最初のスワイプ方向でgesture lockを作る。

以後pointer-upまでこのlockを保持する。

### 2. poleでは挙上面を1回だけ選ぶ

挙上角が約0〜10°または170〜180°のときは、最初のスワイプ方向と最も一致する挙上面を探索する。

選んだ挙上面はそのgesture中固定する。

したがって腕を下ろした状態から挙上しても、途中で前方82°→90°などへ再解釈しない。

### 3. 中間姿勢では関節空間の1本のrayを固定

pole以外ではpointer-down姿勢で画面投影ヤコビアンを1回だけ計算し、最初のスワイプを

- 挙上角
- 挙上面

の比率へ変換する。

その比率を `angleDir` として固定し、そのgesture中は

`pose = anchorPose + λ × angleDir`

の1次元経路上だけを移動する。

現在姿勢からヤコビアンを作り直さない。

### 4. 途中の横ブレを無視

pointer-downから現在位置までの指移動を、最初のscreen directionへ射影する。

そのため途中で指が少し横にぶれても、その成分を新しい肩方向として解釈しない。

### 5. 軸回旋は変更しない

この直接挙上gestureで変更するのは

- `elev`
- `plane`

だけ。

`axial`、`pronation`、`elbow`などは変更しない。

## 回帰テスト

`tests/v071-direction-lock.mjs`

確認項目:

- 0°付近からのgestureで挙上面を1回だけ選択
- gesture中の挙上面driftなし
- 中間姿勢で固定した `elev:plane` 比率を維持
- pointerの途中横ブレで関節方向を再解釈しない
- shoulder axial rotationを変更しない
- pointer-up後の新しいgestureでは新しい方向を選べる

## 限界

これは画面操作の安定化であり、肩関節の真の3D運動軌道を推定するものではない。

現在の `elev / plane / axial` 表現自体にはEuler-likeな特異性が残る。将来的には、直接操作中だけ肩姿勢を固定回転軸またはquaternion pathで保持し、UI表示用に角度へ分解する方式の方がさらに頑健。
